# [Week of 2026-05-11] — We wrote more English than Python

---

This week I shipped Feature 001 of FieldKit: an email intake agent that polls Gmail every 5 minutes, enforces an allowlist, assigns a reference ID to each email, and sends a Telegram acknowledgement.

793 lines of Python. 1,334 lines of English spec written before a single line of code.

The spec outweighs the production code nearly 2:1. That was intentional.

---

**The methodology: spec-kit**

Every feature starts with a specification — written entirely in plain English — before any code exists.

For Feature 001 that meant: spec, clarify, tech plan, tasks, a full sequence diagram, and 7 Gherkin feature files describing every behaviour a non-technical business owner can read and verify.

Beyond the feature spec: 400 lines of constitution written before any feature work began — rules governing what the AI agent is and isn't allowed to do, what it must never improvise on, and what requires human approval.

Spec-first sounds slow. It isn't. It catches design problems before they become debugging problems. When production revealed real issues, the fix was: update the spec first, then the code. The spec stays the source of truth.

---

**The counterintuitive part: we used less AI, not more**

This is an AI-powered framework. Feature 001 uses the LLM exactly once: to receive the `/check_email` command and dispatch a single bash command. Everything after that — Gmail polling, allowlist enforcement, ref ID assignment, Telegram delivery — is deterministic Python.

Why? Because an email intake pipeline has no room for probabilistic behaviour. Either the email is acknowledged or it isn't. Either the ref ID is unique or it isn't.

The LLM dispatches. Python delivers.

---

**Adversarial review is now part of the workflow**

After all 7 tasks passed, we ran a dedicated adversarial review agent — tasked with finding every real problem, with no instruction to be polite about it.

It found 15 findings across Critical, High, Medium, and Low. All real. Among them: silent Telegram failures that were completely invisible, and stale entries being dequeued before confirming the alert email was sent.

All 15 fixed. 28 automated tests. Adversarial review is now a permanent gate before any feature ships.

---

**The honest ops lesson**

The code took two days. Getting the system cron working correctly took three.

The macOS Keychain is inaccessible from a cron job — no user session. The Gmail CLI silently deleted its own credentials file the first time cron ran.

Real builds are messier than tutorials. That's the point of building in public.

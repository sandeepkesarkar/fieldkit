# [Week of 2026-08-31] — I open-sourced the methodology, then used it to catch a bug that would've broken a real post

---

It's been a couple months since the last update here — heads-down building, not posting. Here's what that time went into.

Back in May I wrote about running a single "critical reviewer" AI agent as a mandatory gate after every feature — no diplomacy, just "find everything wrong with this." It worked well enough that I kept pulling on the thread: what if the whole dev lifecycle worked this way? Requirements gathered through relentless Q&A before any code gets touched. Work broken into small, dependency-ordered issues. Every PR gated on real coverage and integration tests. A different AI vendor reviewing every diff, never the one that wrote it. All of it enforced, not just suggested.

That became [agent-dev-kit](https://github.com/sandeepkesarkar/agent-dev-kit) — a spec-first, multi-agent development framework, open-sourced (MIT). I designed it to cover the whole path from a human's first sentence to a merge-ready, cross-vendor-reviewed PR. What's actually proven so far, live, against real production code, is the back half: implement, gate on real coverage and integration tests, get reviewed by a different AI vendor, merge only by a human. Getting the front door — turning a vague ask into an approved spec — to work reliably turned out to be the harder engineering problem. That's most of what's below.

Then I used the back half, live, to build FieldKit — and it held up under real pressure. In one run, the cross-vendor reviewer caught a bug that would have quietly turned a 4-second video into a 10-minute one before it ever reached a real client. In another, it caught a real injection-class vulnerability in how a client's name got embedded into a video filter. Neither would have been obvious from reading the diff alone.

The front door was the harder story. A routing rule I was relying on got silently skipped three separate times, in three separate ways — and the actual fix wasn't a better prompt, it was accepting that some things need a deterministic guardrail instead of an instruction the model can route around. That fix is still mid-build. I wrote up the full story, including the parts that don't work yet, in the article linked below.

# [Week of 2026-09-22] — A $20 lesson in how multi-agent setups spend your money

---

On Monday night my AI orchestrator ran code reviews while I slept. That's the point of it. By Tuesday evening my Anthropic API key had hit its $20 monthly spend limit, and my Telegram bot started replying with "You have reached your specified API usage limits."

My setup is supposed to run on flat-rate subscriptions: Claude Code implements, Codex reviews. So where did pay-per-token usage come from?

The trail took an evening to follow:
→ The orchestrator checks which agent CLIs are installed and treats any it finds as a usable worker. I'd installed another agent (Hermes) weeks earlier for something unrelated.
→ Its rule was "have a *different* vendor review every change", so for a second opinion it started three extra review sessions on that agent, about 330 tool calls across two PRs.
→ That agent reads its own model config, which pointed at my pay-per-token API key. None of my subscriptions were involved.
→ One layer deeper: it was launched from a folder with no project config, so it used the tool's built-in default orchestrator instead of mine.

Nobody configured "use this agent and bill the API". It came out of defaults.

The spend limit worked: it hard-stopped the calls at $20. It also did what hard limits do and blocked everything else on that key, including my Telegram bot, until the next billing cycle. A spend limit is a circuit breaker, not a fix.

I traced it and had the fixes merged by Tuesday night. Most of that time went to finding the cause; each fix was only a few lines.

What I changed:
1. A short allow-list of workers (Claude Code implements, Codex only reviews) instead of "whatever is installed".
2. Removed API keys from every agent tool that should be on a subscription, so there's nothing to fall back to.
3. My orchestrator config is now the machine-wide default, with an absolute path. A relative path had been failing silently.

Next: one key per purpose, so a cap tripping in one place can't take down another.

The lesson: in a multi-agent setup, cost is decided by each tool's local config, not just the orchestrator's. Set a spend limit on every API key before anything runs unattended. Then work out what else breaks when that limit trips.

# [Week of 2026-05-18] — Shipped Feature 002: photo-to-video pipeline with human-in-the-loop approval

---

Shipped Feature 002 of FieldKit this week — a fully automated photo-to-video pipeline with a human-in-the-loop approval gate.

Here's what it does end-to-end:

→ Pulls photos from a Google Drive folder
→ Generates an MP4 slideshow via FFmpeg
→ Uploads the video back to Drive
→ Sends a Telegram message with Approve / Reject buttons
→ On approval: emails a confirmation and cleans up local temp files
→ On rejection: deletes the video from Drive and prompts to re-trigger

The whole thing is triggered by a `/process_photos` command in Telegram and runs headless on a Mac Mini.

**What I found interesting this week: the critical review pattern.**

After finishing the implementation I ran a separate AI agent with one job — find everything wrong with the code. No diplomacy. It caught things I wouldn't have caught in a normal review:

- A state atomicity bug where an exception in the activity logger could bypass `clear_pending_approval()`, leaving the pipeline permanently stuck
- PII leaking into debug logs (Telegram chat ID)
- A cross-chat spoofing vector — callback queries were matched on `message_id` alone, not `message_id` + `chat_id`
- Crash-unsafety in the state file writer (truncate-before-write leaves an empty file on crash; write-then-truncate doesn't)

Running a critical reviewer as a mandatory gate after every feature has become a core part of how I build with Claude Code. The cost is low; the signal is high.

**The AI-assisted dev workflow (spec-kit) is also working well.** Each feature goes through: spec → clarify → techplan → task breakdown → Gherkin scenarios → implementation. It sounds heavyweight but it keeps scope tight and makes the handoff between sessions coherent.

Feature 002: 204 unit tests, two critical review passes, smoke tested end-to-end. Building in public — more to come.
